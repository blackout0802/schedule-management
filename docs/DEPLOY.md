# スターレンタルサーバーへの導入手順

所要時間の目安は 30〜60 分です。「（要確認）」と付いた項目は、サーバーパネルの画面を見て確認してください。

## 0. 用意するもの

- スターレンタルサーバーのサーバーパネルにログインできること
- 独自ドメインまたは提供ドメインで **https（SSL）** が使えること（ログイン情報を守るために必須です）
- Slack通知を使う場合: Slackワークスペースでアプリを追加できる権限

## 1. PHPとデータベースの準備（サーバーパネル）

1. **PHPのバージョン**を 7.4 以上（8.x 推奨）にします。（要確認: サーバーパネルの「PHP Ver.切替」）
2. **MySQLデータベースを1つ作成**します。次の4つをメモします。（要確認: サーバーパネルの「MySQL設定」）
   - データベース名 / ユーザー名 / パスワード / ホスト名（`localhost` とは限りません）

## 2. ファイルをアップロードする

次のどちらかを選びます。**方式Aの方が安全です**（設定ファイルが外から見えない場所に置けます）。

### 方式A（おすすめ）: 公開フォルダの外に本体を置く

```
/home/ユーザー名/schedule_app/     ← 公開フォルダ(public_html)の外。src, sql, bin, config.php を置く
/home/ユーザー名/.../public_html/schedule/   ← public フォルダの「中身」だけを置く
```

1. `src` `sql` `bin` `config.sample.php` を `schedule_app` にアップロードします。
2. `public` フォルダの**中身**（index.php, login.php, api.php, assets など）を `public_html/schedule/` にアップロードします。
3. 画面を置いたフォルダから見て**2つ上の階層**に `schedule_app` フォルダがあれば、自動で見つかります（例: `…/public_html/schedule/` なら `…/schedule_app/`）。この配置なら書き換えは不要です。別の場所に置いた場合だけ、`app_path.php` の絶対パスを書き換えます。

### 方式A'（これまでのアプリと同じく public_html の中に置く）

本体の `schedule_app` を、`public_html` の中の、画面のフォルダの**隣**に置きます（例: `public_html/schedule_app/` と `public_html/サイト名/`）。

- `schedule_app` の直下に `.htaccess`（リポジトリ直下のものと同じ「アクセス拒否」の設定）を**必ず置いてください**。これで `config.php` などがURLから見えなくなります。（Apache 2.4 で、`config.php`・`src`・`sql`・`bin` が403になることを確認済みです。サーバー側で `.htaccess` が使える設定になっているかは、手順5で確認してください。）
- 方式Aより少し弱い点: 「公開フォルダの外」ではなく、`.htaccess` に守りを頼る形になります。

### 方式B（いちばん簡単）: 一式を公開フォルダに置く

1. プロジェクト一式を `public_html/schedule/` にアップロードします。
2. 画面のURLは `https://ドメイン/schedule/public/` になります。
3. 各フォルダの `.htaccess` が外部からの直接アクセスを防ぎます。**手順5の確認を必ず行ってください。**

## 3. データベースの情報を入れる

**おすすめ: 手順4の画面に貼り付ける（`config.php` を手で書かなくてよい）**

手順4で `install.php` を開くと、データベースの情報（ホスト名・データベース名・ユーザー名・パスワード）を入れる欄が出ます。サーバーパネルの「MySQL設定」に表示されている値を入力すると、接続を確かめてから `config.php` を自動で作ります。間違いがあれば、原因（パスワード違い・データベース名違い・権限なし）を表示します。

自動で保存できないサーバーでは、完成した `config.php` の内容が画面に表示されるので、それを保存してアップロードします。

**手で書く場合**: `config.sample.php` を `config.php` という名前でコピーし、データベースの情報を書きます。

```php
'db' => [
    'dsn'  => 'mysql:host=ホスト名;dbname=データベース名;charset=utf8mb4',
    'user' => 'ユーザー名',
    'pass' => 'パスワード',
],
```

## 4. 初期設定（管理者の登録）

1. ブラウザで `https://ドメイン/schedule/install.php`（方式Bは `/schedule/public/install.php`）を開きます。
2. 手順3のデータベース情報を入力します（`config.php` を手で作った場合は、この手順は飛ばされます）。続けてテーブルが自動で作られ、名前・メールアドレス・パスワード（8文字以上）を入れて、最初の管理者を登録します。
3. **登録できたら、`install.php` をサーバーから削除します。**（消し忘れても、登録後は接続先を書き換えられませんが、不要なファイルは置かないのが安全です）

## 5. 安全の確認

次のURLを開いて、**どれも表示されない**（403 または 404 になる）ことを確認します。

- 方式B: `https://ドメイン/schedule/config.php`、`/schedule/src/bootstrap.php`、`/schedule/sql/schema.mysql.sql`
- 設定ファイルの中身が見えてしまった場合は、すぐに方式Aに切り替え、データベースのパスワードを変更してください。
- サーバーパネルで、**独自SSL（https）を有効**にし、`http://` で開いても `https://` に移るようにしてください（パスワードが暗号化されずに流れるのを防ぎます）。
- 管理者のパスワードは、12文字以上など、長いものにしてください（管理者は、バックアップの取得・復元など、重要な操作ができるため）。
- ログインに何度も失敗すると、15分間は試せなくなります（本人が間違え続けたときも同じです。15分待てば戻ります）。

## 6. 社員を追加する

ログイン → 右上の名前 → **社員の管理** → **＋社員を追加**。名前、メールアドレス、**初期パスワード**（8文字以上）を入れ、本人に伝えます。
管理者にしたい人は権限を「管理者」にします。

- 管理者が登録した人は、**最初のログイン時に「パスワードの変更」の案内が出て、変更するまで予定の画面に進めません**（画面を閉じる操作もできません）。
- パスワードを忘れた人は、管理者が「設定」の「社員の管理」で、その人の **「パスワードをリセット」** を押します。一時パスワードが1度だけ表示されるので、本人に伝えてください（本人は次のログイン時に、自分のパスワードへ変更します。ログイン失敗によるロックも解除されます）。
- **バックアップ**: 管理者の設定「バックアップ」から、データを暗号化したファイルをダウンロードできます（プライベートの予定も含みます）。月に1回など、定期的に取り、**パスワードは、ファイルとは別の場所に**控えてください（忘れると復元できません）。`config.php`（DBの接続設定）はファイルに含まれないので、別に控えます。復元は、同じ画面（ファイル＋パスワード＋「復元する」と入力）か、サーバーのコマンド `BACKUP_PASSWORD=… php bin/restore_backup.php ファイル` で行います。サーバーのDB（MySQL）自体のバックアップ機能も、併用すると安心です。
- **コメントの画像**: 保存先 `data/attachments/` は、サーバーが書き込めるようにしておきます（自動で作られます）。PHPの `upload_max_filesize` が小さすぎる（2MB未満）と、大きな画像が送れません（ブラウザ側で1枚900KB前後に縮めるので、ふつうは2MBで足ります）。PHPの GD 拡張があると、画像を描き直して保存します（無い場合は2MBまでをそのまま保存）。画像はバックアップのファイルに含まれないので、必要なら `data/attachments/` を別にコピーしてください。\n- **自動バックアップ**: 設定「バックアップ」でパスワードを決めると、毎日、暗号化したバックアップが `data/backups/` に保存されます（Slack通知用の cron `bin/cron.php notify` の中で動くので、cron の追加は不要です。まだ通知用の cron を登録していない場合は、5〜10分おきに `php bin/cron.php notify` を登録してください）。ただし、同じサーバーの中なので、サーバーが壊れると一緒に失われます。**月1回は、手動でダウンロードして別の場所に保管**してください（30日たつと、管理者の画面にお知らせが出ます）。
- **管理者自身が忘れたとき**は、サーバーのコマンドで一時パスワードを設定できます: `php bin/reset_password.php 管理者のメールアドレス`（一時パスワードが表示されます。`php bin/reset_password.php メールアドレス 新しいパスワード` で、8文字以上の指定もできます。Web からは動きません）。
- 社員の一覧に「（初回パスワード未変更）」と出ている間は、まだ本人が変更していません。

## 7. 繰り返し業務を登録する

右上の名前 → **繰り返し業務の設定** → 「よくある月次業務の例（6件）をまとめて登録」。次のように登録されます。実際の運用に合わせて「編集」で変えてください。

| 業務 | ルール |
|---|---|
| 請求処理 | 月初から3営業日（1営業日目〜3営業日目の期間） |
| 給与計算の準備 | 10日〜15日（土日祝を除く） |
| 棚卸し | 20日〜25日（土日祝は含めない） |
| シフト提出 / 住民税の金額チェック / 支払請求書のスキャン | 25日（休日なら前の営業日） |

年末年始などの会社の休業日は、**会社の休業日**（管理者メニュー）に登録すると、日付計算に反映されます。

## 8. Slack通知の設定

1. <https://api.slack.com/apps> で **Create New App → From scratch** を選び、アプリ名とワークスペースを選びます。
2. **Incoming Webhooks** を ON にし、**Add New Webhook to Workspace** で通知先のチャンネルを選びます。
3. 表示された `https://hooks.slack.com/services/…` のURLをコピーします。次のどちらかで登録します。
   - **画面から（おすすめ）**: 管理者でログインし、右上の **「設定」→「Slack通知の設定・テスト」** を開いて、**チャンネル名**（自分で分かる名前）と URL を入れて「追加して保存」。チャンネルごとに最大10件まで登録でき、**プルダウンで通知先を選ぶ**と、すぐ切り替わります。FTPでファイルを触る必要はありません（Slackの Webhook URL だけ登録できます）。URL は画面に全部は表示されず、サーバーに保存されます。
   - `config.php` に書く:

```php
'slack_webhook' => 'https://hooks.slack.com/services/…',
'base_url'      => 'https://ドメイン/schedule/',   // 通知に付けるリンク（任意）
```

   両方ある場合は、画面から登録したものが優先されます（画面の登録を空にして保存すると、`config.php` の設定に戻ります）。

4. **テスト**: 同じ画面の **「テスト通知を送る」** で、接続の確認ができます。送れなかったときは、原因の案内（URLが無効・チャンネルが見つからない・サーバーから外へ通信できない、など）が出ます。通知の文面の見本は、「通知の時間・文面を変える」の画面から、実際に送って確かめられます。

通知は、**朝（本日の休み）と夕方（次の営業日の休み）の2種類**で、初期値は **休みの人の名前だけ**です（休みの理由・種類・メモは送りません。1人分の書き方は画面で変えられます）。休みを登録したときの通知はありません。通知の時刻・文面は、「設定」→「Slack通知の時間・文面」で変えられます（9章の cron の `notify` が必要です）。

## ホーム画面に追加・変更履歴

- **ホーム画面に追加**: スマホのブラウザで https の画面を開き、「ホーム画面に追加」で、アプリのアイコンを置けます（手順は、設定のページにも出ます）。アイコンや `manifest.php` は、ログインなしで読める必要があります（`public/` の中は、そのまま公開されます）。`https` でないと、ホーム画面に追加するときに、アプリではなくブラウザのショートカットになることがあります。
- **変更履歴**: 管理者は、設定のページの「変更履歴」で、誰が・いつ・何を変えたかを見られます。1年分を保存し、古いものは自動で消えます。データベースの更新（`audit_log` テーブル）は、更新後の最初の画面表示で、自動で行われます。

## 9. 毎日の自動処理（cron）

サーバーパネルの cron 設定に、次の2つを登録します。（要確認: 「Cron設定」画面と、PHPコマンドのパス。`/usr/bin/php8.x` のように、使うPHPのバージョンに合わせた CLI のパスがマニュアルに載っています）

| 時刻 | コマンド | 内容 |
|---|---|---|
| 毎日 0:30 | `/usr/bin/php8.3 /home/ユーザー名/schedule_app/bin/cron.php nightly` | 繰り返し予定を12か月先まで作る |
| 10分おき（毎日） | `/usr/bin/php8.3 /home/ユーザー名/schedule_app/bin/cron.php notify` | Slack の朝・夕方の通知（送る時刻は、画面の **「設定」→「Slack通知の時間・文面」** で決める） |

- **通知の時刻・文面は画面で変えられます**（管理者）。朝（本日の休み）と夕方（次の営業日の休み）の送る時刻・オン/オフ、休みを登録したときの通知のオン/オフ、3つの通知の文章、1人分の書き方、メンションの有無です。文章には `{日付}` `{休み一覧}` `{人数}` `{リンク}` などを差し込めます（画面にボタンがあり、保存前に見本で確認できます）。
- `notify` は、設定した時刻から **3時間以内** に、1回だけ送ります（時刻より後に cron が動いたときだけ送るため、10分おきなら、設定した時刻の10分以内に届きます）。
- 以前の `morning`（平日 8:30）／`evening`（平日 17:00）の cron を使っている場合は、そのままでも動きます（その時刻に、従来どおり送られます。文面は画面の設定が使われます）。`notify` に切り替えるときは、`morning`・`evening` の登録を消してください。

- 土日祝・会社の休業日は、自動でスキップします。営業日で休みの人がいない日は、**「休みなし」と通知します**（文言の変更・オフは、画面の「Slack通知の時間・文面」で）。
- 同じ内容は二重に送りません。送信に失敗した場合は、次の実行で再送します。
- 繰り返し予定は、ルールを保存した時点で作られるので、`nightly` が動かなくても当面は困りません（12か月を過ぎる前に動くようにしてください）。
- cron が使えない場合の代わりの方法は `bin/cron.php` の冒頭に書いてあります。

## 10. バックアップ

サーバーパネルのデータベースのエクスポート（phpMyAdmin など）で、月に1回ほど保存してください。

## 10-2. 共有リンク（家族・会社の人へ、ログインなしで見せる）

右上の名前 → **「共有リンク（家族・会社へ）」** で、閲覧専用のURLを作れます。

| 種類 | 作れる人 | 見られるもの |
|---|---|---|
| 家族用 | 本人（各自） | カレンダーだけ。自分の予定のうち、**家族に共有すると決めたものだけ**（下記）。リストは出ません |
| 会社用 | 管理者 | 業務の予定と休み。プライベートは（共有にチェックがあっても）出ません。予定のメモも出しません |

Slack の通知に付く「スケジュールを開く」は、会社用リンクがあればそこに飛びます（ログイン不要で、業務カレンダーを閲覧専用で見られます）。会社用リンクを作り直すと、過去の通知のリンクは開けなくなります。まだ作っていなければ、ログイン後に業務版が開くリンクになります。`base_url` は必須です。

家族に見せる予定の決め方（家族用）:

| 種類 | 初期値 | 変え方 |
|---|---|---|
| プライベート | **共有する**（外した予定だけ隠れる） | 予定を開いて「家族に共有する」のチェックを外す |
| 業務・休み | **共有しない**（選んだものだけ共有） | 予定を開いて「家族にも共有する」にチェック。または、共有リンクの画面の **「家族に見せる範囲」** で、「自分の休みをすべて」「業務の分類ごと」にチェックすると、すでに登録してある予定も含めてまとめて共有（外すとすぐ見えなくなる） |

- 他の人の予定を管理者が編集しても、その人の「家族への共有」は変わりません（持ち主だけが決めます）。
- 業務の予定を家族に共有すると、メモ欄の内容も見えます。
- プライベートの予定を入力するときの「家族に共有する」は、**初期値がチェック済み**です。見せたくない予定だけチェックを外します（外した予定には「非共有｜」と表示されます）。
- ログインは不要で、**見るだけ**です（編集・追加・ToDo・メモは出ません）。
- URLを知っている人は誰でも見られるので、見せたい人にだけ伝えてください。伝わりすぎたときは、「リンクを作り直す」（古いURLはすぐ無効）か「共有を止める」を押します。
- 本人が利用停止になると、その人の家族用リンクも使えなくなります。

## 10-3. 画面の自動更新

他の人が予定やToDoを変えたとき、開いている画面（共有リンクのページも）に、**約20秒以内に自動で反映**されます。

- 共有レンタルサーバーでは、サーバーから画面へ即時に知らせる方式が使えないため、画面が「更新番号」を20秒ごとに軽く確認する方式です（1人あたり1分に3回程度の、ごく軽い確認）。
- 更新番号が変わったときだけ予定・ToDoを読み直します。変わっていなければ、何も描き直しません。
- 予定の編集画面を開いている間と、ドラッグしている間は、画面を組み替えません（閉じたあと・離したあとに反映）。入力途中のToDoの文字も消えません。
- タブが非表示のときは確認せず、見えるようになった瞬間に確認します。
- 自分の更新は、すぐ画面に出ます（20秒待つ必要はありません）。
- メモ（日報用）は、自分だけの内容なので、自動更新の対象ではありません。
- 間隔を変えたい、やめたいときは、`config.php` に `'poll_seconds' => 20,`（5〜600。0で自動更新なし）と書きます。

## 11. 更新するとき

プログラムの更新は、**GitHub から自動で反映**されます（下の「11-2」）。管理者の画面から、zip を選んで更新する機能は、ありません。

- 更新後は、画面を開き直し（Ctrl + F5）、画面タイトルの横の版の数字が上がったことを確認します。
- 画面の更新に伴うデータベースの変更（テーブルの追加など）は、画面を開いたときに**自動で**行われます。
- `config.php`（データベースの設定）、`data`、`.htaccess`、`install.php`、`app_path.php` には、触れません。
- おかしくなったときは、開発側に連絡して、前の版に戻してもらいます。

## 11-2. サーバーへの自動反映（GitHub Actions → FTPS）

zip を使わずに、GitHub にプッシュしたあと、テストがすべて成功したら、サーバーへ**自動で**反映する仕組みです（`.github/workflows/test.yml` の `deploy`）。

- 反映するのは、`public`・`src`・`sql`・`bin` の中の、アプリのファイルだけです（`tools/stage_deploy.py` がそろえます）。`config.php`・`data`・`.htaccess` には触りません。
- 反映するのは、作業ブランチ（`claude/intelligent-brahmagupta-qhk963`）へのプッシュのときだけです。テストが1つでも失敗すると、反映しません。
- データベースの変更は、画面を開いたときに自動で行われます。

### 初めに1回だけ: Secrets の登録

GitHub のリポジトリ → **Settings → Secrets and variables → Actions → New repository secret** で、次の4つを登録します。（登録するまでは、反映は行われませんが、テストは失敗にもなりません）

| 名前 | 入れるもの | 例 |
|---|---|---|
| `FTP_SERVER` | FTP のホスト名 | `ss912764.stars.ne.jp` |
| `FTP_USERNAME` | FTP のユーザー名 | `ss912764` |
| `FTP_PASSWORD` | FTP のパスワード | （FileZilla のサイトマネージャーと同じもの） |
| `FTP_SERVER_DIR` | サーバー側の、アプリのフォルダ（`config.php` と `public` フォルダがある場所）。**最後の `/` は、付け忘れても、自動で補う** | `/schedule-management.skym.ink/public_html/` |

- パスワードは、チャットやファイルには書かず、Secrets の画面にだけ入れてください。登録した値は、あとから見ることはできません（上書きだけできます）。
- **`FTP_SERVER_DIR` は、`public` フォルダの「1つ上」です**（画面のURLが `…/public/index.php` のとき、`index.php` がある `public` フォルダそのものではありません）。`public` フォルダの中を指すと、ファイルが `public/public/…`・`public/src/…` に入り、画面が新しくならず、外から見えてはいけないファイルが公開されてしまいます（このときは、反映を止めます）。
- `FTP_SERVER_DIR` は、FileZilla の右側（サーバー側）で、`config.php`・`public`・`src`・`sql`・`bin`・`data` が並んでいるフォルダを開いたときの、上のほうの「リモートサイト」に出るパスです。
- 接続は、FileZilla と同じ「使用可能なら明示的な FTP over TLS」（FTPS）です。証明書のエラーが出たときは、`deploy` の `security: loose` を足します。

### うまくいったかの確認

プッシュ後、GitHub の **Actions** → 最新の `tests` → `deploy` を開きます。緑なら反映済みです。サーバーの画面を開き直し（Ctrl + F5）、画面左上のバージョンが上がっていれば確認できます。

## こんなときは

| 症状 | 確認すること |
|---|---|
| 「データベースに接続できません」 | `config.php` のホスト名・データベース名・ユーザー名・パスワード |
| ログインできない | https で開いているか。パスワードは管理者が「社員の管理」で「パスワードをリセット」できます（管理者本人は `bin/reset_password.php`）。短時間に失敗しすぎると、しばらくロックされます |
| 「403 Forbidden」（スターサーバーの画面）が出る | FileZilla で `login.php` などを右クリック →「ファイルのアクセス権」を確認し、ファイルは **644**、フォルダは **755** にする（666 や 777 だと拒否されます）。直らなければ、そのファイルを PC から上書きアップロードし直す |
| 画面が真っ白 | PHPのバージョンが 7.4 以上か。サーバーのエラーログを確認 |
| Slackに届かない | Webhook URL が正しいか。サーバーのエラーログに `[schedule] Slack通知` が出ていないか |
