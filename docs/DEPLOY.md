# スターレンタルサーバーへの導入手順

所要時間の目安は 30〜60 分です。「（要確認）」と付いた項目は、サーバーパネルの画面を見て確認してください。

## 0. 用意するもの

- スターレンタルサーバーのサーバーパネルにログインできること
- 独自ドメインまたは提供ドメインで **https（SSL）** が使えること（ログイン情報を守るために必須です）
- Slack通知を使う場合: Slackワークスペースでアプリを追加できる権限

## 1. PHPとデータベースの準備（サーバーパネル）

1. **PHPのバージョン**を 7.4 以上（8.x 推奨）にします。（要確認: サーバーパネルの「PHP Ver.切替」）
2. **MySQLデータベースを1つ作成**します。次の4つをメモします。（要確認: サーバーパネルの「MySQL設定」）
   - データベース名 / ユーザー名 / パスワード / ホスト名（`localhost` とは限りません）

## 2. ファイルをアップロードする

次のどちらかを選びます。**方式Aの方が安全です**（設定ファイルが外から見えない場所に置けます）。

### 方式A（おすすめ）: 公開フォルダの外に本体を置く

```
/home/ユーザー名/schedule_app/     ← 公開フォルダ(public_html)の外。src, sql, bin, config.php を置く
/home/ユーザー名/.../public_html/schedule/   ← public フォルダの「中身」だけを置く
```

1. `src` `sql` `bin` `config.sample.php` を `schedule_app` にアップロードします。
2. `public` フォルダの**中身**（index.php, login.php, api.php, assets など）を `public_html/schedule/` にアップロードします。
3. `public_html/schedule/app_path.php` を開き、`/home/ユーザー名/schedule_app` を実際の場所に書き換えます。

### 方式B（いちばん簡単）: 一式を公開フォルダに置く

1. プロジェクト一式を `public_html/schedule/` にアップロードします。
2. 画面のURLは `https://ドメイン/schedule/public/` になります。
3. 各フォルダの `.htaccess` が外部からの直接アクセスを防ぎます。**手順5の確認を必ず行ってください。**

## 3. 設定ファイルを作る

`config.sample.php` を `config.php` という名前でコピーし、データベースの情報を書きます。

```php
'db' => [
    'dsn'  => 'mysql:host=ホスト名;dbname=データベース名;charset=utf8mb4',
    'user' => 'ユーザー名',
    'pass' => 'パスワード',
],
```

## 4. 初期設定（管理者の登録）

1. ブラウザで `https://ドメイン/schedule/install.php`（方式Bは `/schedule/public/install.php`）を開きます。
2. テーブルが自動で作られます。名前・メールアドレス・パスワード（8文字以上）を入れて、最初の管理者を登録します。
3. **登録できたら、`install.php` をサーバーから削除します。**

## 5. 安全の確認

次のURLを開いて、**どれも表示されない**（403 または 404 になる）ことを確認します。

- 方式B: `https://ドメイン/schedule/config.php`、`/schedule/src/bootstrap.php`、`/schedule/sql/schema.mysql.sql`
- 設定ファイルの中身が見えてしまった場合は、すぐに方式Aに切り替え、データベースのパスワードを変更してください。

## 6. 社員を追加する

ログイン → 右上の名前 → **社員の管理** → **＋社員を追加**。名前、メールアドレス、最初のパスワードを入れ、本人に伝えます（ログイン後に「パスワードの変更」から変えてもらいます）。
管理者にしたい人は権限を「管理者」にします。

## 7. 繰り返し業務を登録する

右上の名前 → **繰り返し業務の設定** → 「よくある月次業務の例（6件）をまとめて登録」。次のように登録されます。実際の運用に合わせて「編集」で変えてください。

| 業務 | ルール |
|---|---|
| 請求処理 | 月初から3営業日（1営業日目〜3営業日目の期間） |
| 給与計算の準備 | 10日〜15日（土日祝を除く） |
| 棚卸し | 20日〜25日（土日祝を除く） |
| シフト提出 / 住民税の金額チェック / 支払請求書のスキャン | 25日（休日なら前の営業日） |

年末年始などの会社の休業日は、**会社の休業日**（管理者メニュー）に登録すると、日付計算に反映されます。

## 8. Slack通知の設定

1. <https://api.slack.com/apps> で **Create New App → From scratch** を選び、アプリ名とワークスペースを選びます。
2. **Incoming Webhooks** を ON にし、**Add New Webhook to Workspace** で通知先のチャンネルを選びます。
3. 表示された `https://hooks.slack.com/services/…` のURLをコピーし、`config.php` に書きます。

```php
'slack_webhook' => 'https://hooks.slack.com/services/…',
'base_url'      => 'https://ドメイン/schedule/',   // 通知に付けるリンク（任意）
```

4. 休みを1件登録してみて、Slackに「【休みの登録】」が届けば完了です。
5. 名前にメンション（@名前）を付けたい場合は、社員の管理でその人の **SlackのメンバーID** を登録します（Slackでプロフィールを開き「︙」→「メンバーIDをコピー」。`U` で始まる文字列）。

通知の内容は **件名と日付だけ**です。休みの理由やメモは送りません。

## 9. 毎日の自動処理（cron）

サーバーパネルの cron 設定に、次の3つを登録します。（要確認: 「Cron設定」画面と、PHPコマンドのパス。`/usr/bin/php8.x` のように、使うPHPのバージョンに合わせた CLI のパスがマニュアルに載っています）

| 時刻 | コマンド | 内容 |
|---|---|---|
| 毎日 0:30 | `/usr/bin/php8.3 /home/ユーザー名/schedule_app/bin/cron.php nightly` | 繰り返し予定を12か月先まで作る |
| 平日 8:30 | `/usr/bin/php8.3 /home/ユーザー名/schedule_app/bin/cron.php morning` | 本日の休みをSlackへ |
| 平日 17:00 | `/usr/bin/php8.3 /home/ユーザー名/schedule_app/bin/cron.php evening` | 明日の休みをSlackへ |

- 土日祝・会社の休業日は、自動でスキップします。
- 同じ内容は二重に送りません。送信に失敗した場合は、次の実行で再送します。
- 繰り返し予定は、ルールを保存した時点で作られるので、`nightly` が動かなくても当面は困りません（12か月を過ぎる前に動くようにしてください）。
- cron が使えない場合の代わりの方法は `bin/cron.php` の冒頭に書いてあります。

## 10. バックアップ

サーバーパネルのデータベースのエクスポート（phpMyAdmin など）で、月に1回ほど保存してください。

## 11. 更新するとき

`src` と `public` のファイルを上書きアップロードします。`config.php` は上書きしないでください。テーブルの追加があった場合は、更新の案内に従って `install.php` を一時的に戻します。

## こんなときは

| 症状 | 確認すること |
|---|---|
| 「データベースに接続できません」 | `config.php` のホスト名・データベース名・ユーザー名・パスワード |
| ログインできない | https で開いているか。パスワードは管理者が「社員の管理」で再設定できます |
| 画面が真っ白 | PHPのバージョンが 7.4 以上か。サーバーのエラーログを確認 |
| Slackに届かない | Webhook URL が正しいか。サーバーのエラーログに `[schedule] Slack通知` が出ていないか |
