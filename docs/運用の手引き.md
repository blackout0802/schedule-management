# 運用の手引き（要点）

画面に入れるときは、管理者でログインして、設定の「運用の手引き」（`guide.php`）を開くと、印刷できる1ページがあります。
**この文書は、ログインできない・画面が開かないときのための要点**です。

## 定期的にやること
- 月に1回、設定「バックアップ」から手動バックアップをダウンロードし、**サーバーとは別の場所**に保管する（パスワードは別に控える）。
- ときどき、設定「利用状況」の「気をつけること」を見る。
- 退職した人は、「社員の管理」で**停止**にする。

## 管理者がパスワードを忘れたとき（サーバーのコマンド）
```
cd （アプリ本体のフォルダ。README.md や src フォルダがある場所）
php bin/reset_password.php 管理者のメールアドレス
```
一時パスワードが表示されます。ログインしたら、すぐ変更してください。管理者を2人にしておくと、もう1人がリセットできます。

## 画面が開かない・更新のあとにおかしい
1. サーバーパネルで、サーバーや PHP の状態・エラーログを確認する。
2. 更新直後におかしくなったなら、開発側に連絡して、前の版に戻してもらう（更新は、自動で反映されます）。
3. ログインもできないときは、更新の前に手元に残しておいたファイル一式を、サーバーに上書きして戻す（`config.php` と `data/` は上書きしない）。

## データを戻す（バックアップから）
- 画面から: 設定「バックアップ」→ ファイルとパスワードで「復元する」。
- 画面が開けないとき: `BACKUP_PASSWORD=パスワード php bin/restore_backup.php ファイル` （アプリ本体のフォルダで）。
- 自動バックアップは `data/backups/auto-日時.enc`（毎日 3時以降、最新の30件）。**同じサーバーの中**なので、月1回の手動バックアップも必ず取る。
- `config.php`（DB の接続情報）と、ToDo の画像（`data/attachments/`）はバックアップに入らない。別にコピーしておく。

## cron（サーバーパネルで登録）
```
毎日 0:30   /usr/bin/php8.x （アプリ本体のフォルダ）/bin/cron.php nightly
10分おき    /usr/bin/php8.x （アプリ本体のフォルダ）/bin/cron.php notify
```
`php8.x` は、契約しているサーバーの PHP に合わせます。動いているかは、設定「利用状況」で確認できます。

## 会議室の予約
- 部屋の名前・定員・設備、予約できる時間・先の月数、Slack通知の時刻は、設定の「会議室の設定」で変える（管理者）。
- 年末年始などの休みは、設定「会社の休業日」に登録すると、その日は会議室も予約できなくなる。管理者だけは、休業日や営業時間の外にも予約できる。
- 予約の画面で、**参加者**を選ぶと、その人のカレンダー（業務版）にも予約が出ます。**開始の1時間前の Slack 通知**は、予約ごとにチェックボックスで決めます（cron の `notify` が動いているとき）。
- 予約の変更・取り消しができるのは、予約した本人と管理者だけ。終わった予約は、だれも変更できない（取り消しは、管理者だけができる。間違って残った予約の整理用）。間違いは、変更履歴（種類「会議室」）で確認できる。
- Slack への通知（前日の夕方・当日の朝）は、上の cron の `notify` が動いているときに送られる。

## 安全のために
- 初期設定のあと、`install.php` を削除する。
- https のアドレスだけを使う。ルートの `.htaccess` を消さない。
- プログラムの更新は、GitHub からの自動の反映だけです（接続情報は、GitHub の Secrets にだけ置き、外に出さない）。
