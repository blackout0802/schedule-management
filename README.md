# スケジュール管理アプリ

会社の業務予定・休み（他の社員を含む）・プライベートの予定を1か所で管理する、小規模チーム向けのスケジュールアプリです。
PHP + MySQL だけで動くので、レンタルサーバーにアップロードして使えます（ビルド作業・Node.js は不要）。

## できること

| 機能 | 内容 |
|---|---|
| 業務版 | 会社の全員に見せる画面。**プライベートの予定は、サーバーが返さない**ため、画面を細工しても見えません |
| プライベート版 | 自分のプライベート予定に、**「家族に共有」にした自分の業務・休み**を重ねて表示（家族用リンクで家族に見えるものと同じ。共有は、業務版で予定を開いた「家族にも共有する」のチェック、または共有リンクの「まとめて指定」で決める）。他の社員の予定は出ない（業務版で見る）。以前あった「表示する業務」のチェックは無くなった |
| 休みの管理 | 本人が登録。管理者は他の社員の休みも登録・編集できる（承認は不要） |
| カレンダー | 週ごとの表示。期間のある同じ業務は**1本のバーにまとめ**、土日祝・会社の休業日には出さない。土日祝をはさんで次の週に続くバーは、前後どちらの端も丸くし、「… 」は付けない（土曜から日曜へそのまま続く場合だけ、端を平らにして「… 」を付ける）。予定はドラッグで別の日へ動かせる |
| リスト | 「カレンダー / リスト」の切り替え。**リストタブは、ToDoのカンバン（未着手・進行中・完了）だけ**（予定の一覧は出さない。予定はカレンダーで見る）。リストでは、月の移動・「表示する人」・説明の帯も出ず、見出しは「ToDo（業務／プライベート）」になる。会社用の共有ページのリストだけは、今月の予定を日ごとに並べた一覧 |
| ToDoのカンバン | リストタブでは、ToDoを「未着手・進行中・完了」の3列で管理する。カードをドラッグして列を移せる（列の中での並べ替えも可）。スマホ幅では、列を並べずに状態のタブ（未着手／進行中／完了、件数つき）で切り替え、カードのボタン（進行中へ／完了／戻す）で移す（選んだタブは覚えている）。カレンダー横の細いToDo欄は従来どおりのリストで、進行中のToDoには「進行中」と表示される。ToDoは本人だけに見える |
| 業務のToDoの共有 | **業務のToDoは、社員全員（管理者も）に見える**。業務版のリスト画面に、他の人の業務のToDoが、持ち主の名前つきで出る（見るだけ。ドラッグ・完了・編集・削除はできず、押すと内容とメモが見られる）。上の「表示」で、**全員／自分だけ／○○さん**を選べる（初期値は自分だけ。選んだ状態は、開き直すと自分に戻る）。プライベートのToDoは、これまで通り本人だけ（プライベート版の追加欄で、「プライベート（自分だけ）」か「業務（全員に見える）」を選ぶ）。他の人の更新は、約20秒以内に自動で反映される。利用停止の社員のToDoは出ない |
| ToDoのコメント | **業務のToDoには、持ち主以外の社員も、コメントを付けられる**（編集・完了・削除はできない）。他の人のToDoのカードを押す、または自分のカードの「コメント」ボタンで、コメント欄が開く（500文字まで・Ctrl + Enter で送信・1つのToDoに200件まで）。カードに「💬 件数」が出て、**自分がまだ読んでいないコメントがあると、青い目印**が付く（約20秒以内に自動で反映）。コメントを消せるのは、**書いた人・ToDoの持ち主・管理者**。プライベートのToDoには付けられない。ToDoを削除すると、コメントも消える。コメントは、バックアップに含まれる |
| コメントの画像 | コメントに、**画像（スクリーンショットなど）を3枚まで添付**できる（PNG・JPEG・GIF・WebP）。「📎 画像を添付」で選ぶほか、**貼り付け（Ctrl + V）**や**ドラッグ**でも付けられる。文字なしで画像だけのコメントも可。ブラウザ側で長辺1600pxに縮めてから送り、サーバーでも検査して描き直す（中身が画像でないものは拒否。画像に仕込まれたものや写真の付随情報〔位置情報など〕は消える）。1つのToDoに30枚まで。画像は、サーバーの `data/attachments/`（Webから直接は見えない）に置き、**ログインして、そのToDoを見られる人だけ**が見られる（押すと大きく表示）。コメントやToDoを削除すると、画像も消える。**画像は、バックアップのファイルには含まれない**（バックアップは文字のデータだけ。画像が必要なら、`data/attachments/` を別にコピーする） |
| ToDoの追加 | 上の入力欄・追加ボタンは無く、**未着手の列（カレンダー画面のToDoパネルでは「未着手」）の一番下の「＋ 追加」**を押すと、その場に入力欄が開く（Enterで追加・Escかキャンセルで閉じる。追加後も開いたままなので、続けて入力できる。プライベート版では、種類（プライベート／業務）も選べる） |
| ToDoの完了 | ToDoの左のチェックで完了にすると、リストから消えて「完了したToDo」に移る（日付つき）。チェックを外せば戻り、まとめて削除もできる。今日完了した業務のToDoは、日報の雛形に取り消し線つきで入る |
| 共有リンク | ログイン不要・閲覧専用のURL。**家族用**はカレンダーだけ。自分の予定のうち、家族に共有すると決めたものだけが見える（プライベートは初期値が共有で、外した予定だけ隠れる。業務・休みは初期値が共有なし。既存の予定も、開いてチェックするか、「休みを全て／業務の分類ごと」でまとめて共有できる）。**会社用**（管理者）は、業務の予定と休みだけ。URLの作り直し・停止ですぐ見られなくなる |
| ToDo | **リストタブ**で管理する（カレンダー画面には、ToDoもメモも出さない）。日付の決まっていないやることを置く（**種類が「業務」のToDoは、社員全員に見える**。見るだけで、変えられるのは持ち主だけ。「プライベート」のToDoは本人だけ）。カードを**画面の右端まで持っていくと、カレンダーが開き**、日付にドロップして予定にできる（ドラッグ中に ‹ › へ乗せると月が切り替わる）。スマホなど、ドラッグしにくい端末は、カードの「日付」ボタン。**置いたToDoは消えず、自動で「進行中」になり、リストにも残る**（カードに置いた日が出る。もう一度置くと、予定は新しい日へ動く）。**完了にすると、カレンダーの予定に取り消し線**が引かれる（未完了に戻すと消える。共有リンクにも同じ）。予定をToDoに戻すと、元のToDoに戻る（増えない）。ToDoを削除すると、結びついた予定はふつうの予定として残る。業務版には、業務のToDoだけを表示 |
| メモ（日報用） | リストタブのメモ欄。**1つの入力欄**に、日報の文章をそのまま書く（初めて開くと、「お疲れ様です。〜よろしくお願いいたします。」の雛形が入る）。文章の中の**「【10/13　予定・To Do】」の行（日付の行）が2つあり、上が当日、下が次回出勤日**で、日付は**自動で入れ替わる**（出勤日 = 土日祝・会社の休業日・自分の終日の休みを除く日。半休は出勤日。今日が休みなら、上が次の出勤日になる。日付の行は、直接は書き換えられない）。**日付の間の項目（当日の項目）のうち、取り消し線のないものは、次回出勤日の項目に自動で転記される**（一部でも取り消し線が付いた行は、転記されない）。転記された行は、左に細い線が付く。次回出勤日に自分で書いた行は消えず、同じ内容を自分で書いてあれば、重ねて足さない。**日が進むと、次回出勤日の項目が、当日の項目になる**（前の当日の項目は、取り消し線のないものが、すでに転記済み）。前の日の日報は、「過去の日報」に、120日分の控えが残る。項目は、空行を入れずに並べる（空行で、その見出しの項目が終わる）。いつもの日報の文章を貼り付けると、日付の入った【】の2行が、自動で日付の行になる。予定やToDoは自動では入らない。ToDoのカードを欄にドラッグ&ドロップ（または、カードの「日報へ」）すると、その行が入り、**ToDoが完了なら取り消し線つき**、あとから進捗が変わると行も追従する（次回出勤日の見出しより下へ落とすと、次回出勤日の項目）。終わった業務に**取り消し線**を付けられ（行にカーソルを置いて押せば、その行全体）、「日報にコピー」で、全文を、メール等に貼っても取り消し線が残る形でコピーできる（書式つき + 文字だけ の両方）。「雛形に戻す」で、全文を雛形に置き換える。自動保存・本人だけに見える。以前の版のメモ・日ごとの日報は、最初に開いたとき、雛形に引き継がれる |
| 更新後の自動の開き直し | 「システム更新」が済むと、5秒後に自動で画面を開き直す（Ctrl+F5 不要）。開いたままの他の画面（他の人の画面・家族用リンクも）も、更新に気づくと自動で開き直す。入力画面を開いている間やToDo入力中は、終わるまで待つ。書きかけの日報メモは、保存してから開き直す |
| 自動更新 | 他の人（同僚、共有リンクを見ている家族）が予定・ToDoを変えると、開いている画面に約20秒以内に自動で反映される（ページを開き直す必要なし）。変更があったときだけ読み直す・編集画面を開いている間やドラッグ中は画面を組み替えない・入力中のToDoの文字は消えない・非表示のタブでは確認しない。間隔は `config.php` の `poll_seconds`（5〜600、0で自動更新なし） |
| システム更新 | 管理者メニューから、更新用の zip を選ぶだけでアプリを更新。更新前に自動でバックアップし、画面から元に戻せる |
| 予定の複製 | 予定を開いて「複製」→ 複製先の日付を選ぶ（複数日をまとめて指定可）。期間・時刻・メモを引き継ぐ。同じ予定がある日は飛ばす。休みは Slack に1通でまとめて通知 |
| 会社の休業日 | 右上の名前 →「会社の休業日」（管理者）。1日ずつだけでなく、**開始日〜終了日**で、年末年始などの続く休みをまとめて登録できる（最大60日間・すでにある日は飛ばす）。続く休みは1行にまとめて表示し、まとめて削除もできる。繰り返し業務の日付と、月のまとめの営業日に反映される |
| 文字の太さ | 画面全体の文字を、ふつうの太さ（以前は細め）から**やや太め（600）**にした。もともと太い見出し・ボタンなどは、そのまま。CSSの `--fw` で調整できる |
| カレンダーの右端のToDo | カレンダー画面の右端に「ToDo」の目印があり、**カーソルを持っていくと、ToDoのパネルが開く**（`d` キーでも開閉・Esc で閉じる）。パネルには、**「進行中」「未着手」の2つの欄**が（ToDoが無くても）常に出る。パネルでToDoの追加もでき、カードをカレンダーの日付へドラッグすると予定になる（ドラッグを始めると、パネルは脇へどく）。**カレンダーの予定を画面の右端まで持っていくと、同じパネルが開き**、「進行中」か「未着手」の欄（カードの前後でも可）にドロップすると、その状態のToDoになる。カーソルが離れると閉じる。リストタブでは出ない |
| Slack通知の設定・テスト（管理者） | 右上の **「設定」→「Slack通知の設定・テスト」**。送り先（Slack の Incoming Webhook URL）を、画面から登録・削除できる（`https://hooks.slack.com/services/…` の形だけ。URLは伏せて表示。画面の登録が `config.php` より優先）。**「テスト通知を送る」**で接続を確認し、通知の文面の見本は、「通知の時間・文面」の画面から送れる。失敗したときは、原因の案内が出る |
| システム更新のショートカット | 管理者は、`s` キーで「システム更新」の画面へ移れる（ショートカット一覧にも表示。管理者以外には出ない・動かない） |
| 設定ボタン | 右上に「⚙ 設定」ボタン。押すと、**予定の色の設定・繰り返し業務の設定・共有リンク・ショートカットキー**が出る（管理者には、社員の管理・会社の休業日・システム更新も）。ユーザー名のボタンには、パスワードの変更とログアウトだけが残る。どちらのメニューも、同時に開くのは1つだけ |
| 業務版・プライベート版の切り替え | 画面を作り直さず、**前に読んだ内容がすぐ出て**、あとから最新に差し替わる（初めてでも、カレンダーの枠は消えない）。もう一方の版は、裏で先に読んでおく。素早く往復しても、最後に選んだ版が表示される |
| バージョンの表示 | 画面左上の「スケジュール管理」の右横に、いまのバージョン（例: v1.41.0）が出る |
| ショートカットキー | `c` カレンダー／`l` リスト／`t` 今月に戻る／`←` `→` 前の月・次の月／`n` 予定を追加／`b` 業務版／`p` プライベート版／`?` 一覧。入力欄に文字を打っているとき・ダイアログを開いているとき・Ctrl/Alt/Command を押しているときは動かない。日本語入力がオンでも動く（キーの位置で判定） |
| カレンダーとリストの連携 | カレンダーの予定を、**画面の右端まで持っていくと、ToDoの列（未着手・進行中）が開き**、落とすとToDoになる。ToDoカードを画面の右端へ持っていくとカレンダーが開き、日付に落として予定にできる |
| まとめの行を押す | 月のまとめ（業務版）で社員の行を押すと、「表示する人」でその人を選んだときと同じ表示になる（「全社に戻す」ボタンで戻せる） |
| 表示する人（業務版） | 業務版のツールバーの「表示する人」で、**全社（全員）／自分／他の社員**を切り替える（カレンダー・リストの両方に効く）。**ログインして開いたときは、まず自分のカレンダー・自分のToDo**が出る（選んだ人は覚えない。開き直すと自分に戻る）。ログインせずに見る共有リンク（会社用）は、全員の予定が出る。見える内容は今までどおり（業務と休みだけ。プライベートは誰のものも出ない） |
| 予定の色（人ごと） | 右上の **「設定」→「予定の色の設定」**。**単発の業務・繰り返しの業務・休み・プライベート**の色を、**明るい色が中心の51色（17色相×3段階: 淡い・標準・鮮やか）**か自由な色から選べる。選んだ色が予定の帯の**背景**になり、**文字の色は、背景の色と連動して自動で決まる**（背景と同じ色相で、読める濃さ。明るい背景なら濃い色、暗い背景なら淡い色。候補の51色はすべてコントラスト4.5以上）。重要な予定は、同じ背景色のまま、太字・★・縁取りで目立たせる。**保存すると、他の人の画面（共有リンクを含む）でも、あなたの予定がその色で表示される**（開いたままの画面にも自動で反映）。プライベートの予定の色は、本人の画面だけ。サーバーに保存され、別の端末でも同じ。標準の色は、繰り返しの業務が茶色の文字、単発の業務が青の文字。「すべて標準に戻す」で戻せる |
| 重要な予定 | 予定の入力画面の「★ 重要な予定にする」にチェックすると、カレンダー・リストで、種類の色で塗りつぶした太字＋★になる。持ち主と管理者が付け外しでき、全員の画面・共有リンクで強調される。複製しても引き継ぐ |
| 家族用リンクの更新履歴 | 家族用リンクの画面に、**前回見たときから更新された予定**を ● と色の枠で目立たせるバナーと、「更新履歴」（いつ・何を追加／変更／削除したか）が出る。日付・時刻・件名・分類・メモ・重要の変更が、変更前→変更後つきで残る（最新100件・約4か月分）。「確認した」で目印が消える（ブラウザごとに記憶）。**家族に見えない予定は、履歴にも残らない**。休みは「休み」とだけ。更新前の変更は残らない（この機能を入れた後から記録） |
| Slack通知の時間・文面 | 管理者が画面（設定→Slack通知の時間・文面）で変えられる。朝（本日の休み）・夕方（次の営業日の休み）の**送る時刻とオン/オフ**、2つの通知の**文章**、1人分の書き方（初期値は名前だけ）、休みの人がいない日の通知（初期値は「休みなし」）。保存すると画面は閉じる。`{日付}` `{休み一覧}` `{人数}` `{リンク}` などの差し込みと、保存前の見本付き。時刻で送るには、cron で `bin/cron.php notify` を10分おきに動かす（設定した時刻から3時間以内に1回だけ送る。従来の `morning`/`evening` の cron も、そのまま動く） |
| Slack の送り先 | Webhook URL を、**チャンネル名を付けて最大10件まで**画面（設定→Slack通知の設定・テスト）で保存でき、**プルダウンで通知先を選べる**（選ぶとすぐ切り替わる）。`config.php` の設定も選択肢に出る。URLは画面に全部は出さない。使用中を消すと、残りの先頭（なければ config.php）に自動で切り替わる |
| Slack通知のリンク | 通知の「スケジュールを開く」は、**会社用の共有リンク**（ログイン不要の業務カレンダー）に飛ぶ。会社用リンクがまだ無いときは、ログイン後に必ず業務版が開く入口（`index.php?view=team`）。`config.php` の `base_url` が空ならリンクなし |
| 家族用リンクの削除 | 家族に見えていた予定を削除すると、家族の画面には**取消線で残り**、家族が「確認した」を押すと消える（確認はブラウザごと。ほかの家族には、その人が確認するまで残る。確認しなくても30日で消える）。休みの取消線も「休み」とだけ表示。家族に共有していなかった予定は、残らない。画面の説明文（繰り返し・期間・ショートカット・自動反映）は、家族用では出さない |

| 予定の種類の変更 | 登録した予定は、予定を開いて「業務・休み・プライベート」を選び直すと、あとから切り替えられる。変えられるのは予定の持ち主だけ（管理者でも他の人の予定の種類は変えられない）。プライベート→業務/休みは「全員に見える」確認つき。休みに変えたときは Slack にも通知。家族共有のチェックは、新しい種類の初期値に戻る |
| 毎月の繰り返し業務（入口） | 右上の名前 → 「繰り返し業務の設定」／ツールバーの「↻ 繰り返し業務」／新規予定ダイアログの「繰り返す場合は…」リンク／繰り返し予定を開いたときのリンク |
| 毎月の繰り返し業務 | 「月初3営業日」「10〜15日の営業日」「25日（休日なら前営業日）」などをルールで登録すると、12か月先まで自動で作成。土日祝・会社の休業日を避けて日付を計算 |
| Slack通知 | 毎朝（本日の休み）と夕方（次の営業日の休み）に、**休みの人の名前だけ**を通知（営業日で休みの人がいなければ「休みなし」。休みを登録したときの通知はなし）。理由・種類は載せない |
| ログイン | メールアドレス＋パスワード。管理者が登録した人は、初回ログイン時にパスワードの変更が必要（変更するまで他の操作はできない） |
| 権限 | 一般 / 管理者（社員の追加、他の社員の休みの登録、会社の休業日の設定）。管理者でもプライベートは見えない |

## 見える範囲のルール

| 予定の種類 | 本人 | 他の社員 | 管理者 |
|---|---|---|---|
| 業務 | 見える・編集可 | 見える | 見える・編集可 |
| 休み | 見える・編集可 | 見える | 見える・編集可 |
| プライベート | 見える・編集可 | **届かない** | **届かない** |

この判定は `src/events.php` の1か所だけで行っています。

## セキュリティ

- パスワードは、元に戻せない形（`password_hash`）で保存。ログインは、失敗が続くと一時停止（15分のあいだに、同じメール・同じ接続元で8回／同じ接続元で30回／同じメールで接続元を問わず60回 → 15分。他人がわざと間違えて、本人を締め出せないよう、「8回」は、その接続元だけに効く。リバースプロキシの内側では `trust_forwarded_for` を設定）。パスワードを変えたら、ほかの端末のログインは終わる。ログイン時にセッションIDを作り直し、サーバーが発行していないIDは受け付けない。
- すべての変更操作に、画面ごとの確認用文字列（CSRF）を要求し、**変更の操作は POST だけ**を受け付ける（外のサイトのリンクを踏ませる GET では、何も書き換えられない。読むだけの操作だけ GET で使える）。データベースへの問い合わせは、すべて値を後から渡す形（SQLインジェクション対策）。画面への表示は、文字として出す（XSS対策）。
- 画面ごとの使い捨ての印（nonce）を付けた `<script>` だけを実行し、外部のスクリプト・通信・フォーム送信を許さない（`Content-Security-Policy`）。https のときは `Strict-Transport-Security` も送る。他のサイトの中に埋め込まれることも禁止。
- 他人のプライベート予定は、管理者も含め、サーバー側で返さない。共有リンクは、推測できない48文字のURLで、検索エンジンにも載せない。いつでも無効にできる。
- `config.php`・`src`・`sql` などは、`.htaccess` で外から開けないようにしている（`public/` の外に置く方式Aなら、そもそもURLがない）。
- `install.php` は、ユーザーが1人でも登録されると、接続先の書き換えを受け付けない。データベースに接続できないときなど、「ユーザーがいない」と確かめられないときも閉じたまま（消し忘れても、すり替えられない）。
- **管理者は、システム更新で、プログラムを入れ替えられる**（更新は管理者だけ・拡張子と置き場所は限定・PHPの文法チェックあり。いまより古い版への更新は断る）。**更新用のzipに電子署名は付けていない**ので、管理者のアカウントを乗っ取られると、プログラムを入れ替えられる。管理者は必要な人だけにし、パスワードは、長く推測されにくいものにする。一時パスワードのままでは、バックアップ・システム更新の画面は使えない。

## 動作環境

PHP 7.4 以上／ MySQL または MariaDB。必要なPHPの拡張: **pdo_mysql**（SQLiteで試すなら pdo_sqlite）、**mbstring**、**zip**（システム更新）、**gd**（コメントの画像）、**openssl**・**zlib**（バックアップの暗号化と圧縮）、**curl**（Slack通知）。PHP 7.4 / 8.1 / 8.3 で、自動テストを流しています（`.github/workflows/test.yml`）。

## 手元で試す

```bash
cp config.sample.php config.php
# config.php の db を SQLite にする:  'db' => ['dsn' => 'sqlite:' . __DIR__ . '/data/app.sqlite'],
php -S 127.0.0.1:8080 -t public
# ブラウザで http://127.0.0.1:8080/install.php を開いて管理者を登録
```

## テスト

```bash
php tests/run.php                       # SQLite（一時DB）で実行
SCHEDULE_TEST_DSN='mysql:host=localhost;dbname=テスト用DB;charset=utf8mb4' \
SCHEDULE_TEST_USER=ユーザー SCHEDULE_TEST_PASS=パスワード php tests/run.php   # MySQLで実行（テスト用DBの中身は消えます）
```

祝日の計算、繰り返しルールの日付、プライベートが他人に漏れないこと、管理者の権限、繰り返し予定の個別編集・削除、Slack通知の二重送信防止などを確認します。

```bash
bash tests/e2e/run.sh                   # 画面テスト（Chromiumを動かす。40本ほど。SQLiteで自動）
bash tests/e2e/run.sh who sum           # 名前を指定して、それだけ
```

画面テストは、ログイン・カレンダー・ToDo・日報・共有リンク・バックアップなどを、実際の画面から操作して確かめます。必要なもの・MySQLで動かす方法・テストの一覧は [tests/e2e/README.md](tests/e2e/README.md) を見てください（本物の `data/` や `config.php` には触りません）。機能を変えたら、`tests/run.php` と両方を流します。

導入手順は [docs/DEPLOY.md](docs/DEPLOY.md) を見てください。
